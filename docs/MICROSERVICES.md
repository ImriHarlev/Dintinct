# Microservices Table

All services are .NET 9, containerized, deployed via OpenShift. Each NetworkA service connects only to Postgres-A and RabbitMQ-A (via PgBouncer). Each NetworkB service connects only to Postgres-B and RabbitMQ-B (via PgBouncer). The Proxy is third-party and listed here for reference only.

> **Stack (pinned):** **RabbitMQ 4.3**, **quorum queues**, **3-node cluster per network** ([docs](https://www.rabbitmq.com/docs/quorum-queues)); **PostgreSQL 16** ([docs](https://www.postgresql.org/docs/16/index.html)). 4.x quorum queues provide native message priority (32 strict levels, 0–31) — used for per-`callingSystemId` job priority (§6.1).

> **Service count: A = 11, B = 7** (incl. one `DLQ.Consumer` per network). The converter is **engine-grouped** (see "Service-to-Queue Mapping" below and [ARCHITECTURE.md §3.1/§5.1/§10 #23](ARCHITECTURE.md)): A's `Convert.Worker` is **one codebase deployed 3×** by `CONVERTER_GROUP` — `image` (ImageMagick), `doc` (Aspose), `video` (ffmpeg) — each with its own queue, image, and `consumer_timeout`; B's `ReverseConverter.Worker` is **one codebase deployed 2×** — `image`, `doc` (no `video`: all A/V deliver as-is). Pass-through + rename-to-TXT files (`converter_group=NULL`) skip the converter entirely. Per-row **done-state CAS** is the universal dedup primitive; liveness/recovery is RabbitMQ redelivery + `consumer_timeout` (no per-row heartbeat, no per-phase sweeper — see [ARCHITECTURE.md §3.3](ARCHITECTURE.md) and "Recovery & Calibration" below). Next-step Rabbit publishes go through a transactional `outbox` table and a per-network **OutboxRelay** process. Diagrams: [`architecture-v3.drawio`](architecture-v3.drawio), [`cas-heartbeat-recovery.drawio`](cas-heartbeat-recovery.drawio), [`chunk-flow.drawio`](chunk-flow.drawio), [`worker-exception-handling.drawio`](worker-exception-handling.drawio).
>
> Defaults: `max_retries=5`, `timeout_sla=30min` (per-`callingSystemId` with `default` fallback — §6.1), `priority=0` (per-`callingSystemId`, §6.1), RabbitMQ `consumer_timeout=30min` (tune from metrics; broker-level, not per-caller — **set per engine-group queue**: `files.convert.{image,doc,video}` / `files.reverse.{image,doc}` differ by orders of magnitude, e.g. sub-second image vs minutes-long 6 GB video), `prefetch=1`, quorum `delivery-limit=20` (4.x default; pinned explicitly via policy).
>
> Note: the 4-channel ingestion split is the user's choice; reviewers proposed one Ingestion service. See [`QUESTIONS-TO-CLIENT.md`](QUESTIONS-TO-CLIENT.md) §7.

Network A has **no per-phase row sweeper**. A stuck/crashed worker is recovered by RabbitMQ redelivery + the client-side **watchdog** (recovers a hung-but-alive worker in seconds, faster than `consumer_timeout` — see "Recovery & Calibration"). Job-level progress is guaranteed by the `files_manifest_written_count` counter + per-file DLQ-terminal, backstopped by a job-level **`TimeoutSweeper-A`** (ARCHITECTURE.md §3.7, 30-min SLA) that forces any `source_file` stranded by a watchdog-evading hang or a wedged dead-letter target to `Failed` so `AllManifestsWritten` is always reached. The sweeper runs on a single sweeper-enabled replica (`SWEEPER_ENABLED=true`) — co-located with **OutboxRelay-A** (which already runs as a small always-on replica set), not a new service. See "Recovery & Calibration" below.

## Shared Infrastructure (per network)

| Component | Role |
|-----------|------|
| **RabbitMQ 4.3** | **Quorum queues (decided), 3-node cluster per network** (odd-sized for Raft majority → each queue replicated across all 3, survives one node loss; single node is a broker SPOF, [`QUESTIONS-TO-CLIENT.md`](QUESTIONS-TO-CLIENT.md) §20). `consumer_timeout` is enforced on quorum queues (default 30 min); the client-side watchdog reclaims a hung worker faster (ARCHITECTURE.md §3.3). Classic queue mirroring was removed in 4.0 and is not used. **Shared retry/dead pattern per network** (19 queues total across both networks after the converter engine split — A: 5 main + 1 retry + 1 dead = 7; B: 10 main + 1 retry + 1 dead = 12; the engine split adds only **main** queues, retry/dead stay shared and unchanged): one shared `retry` queue + one shared `dead` queue per network; one `retry` exchange (direct, routes INTO the retry queue) and one `reroute` exchange (direct, routes OUT of retry back to main queues after TTL). Workers on transient failure publish to the `retry` exchange with routing key = original queue name; on exhaustion or permanent failure publish to the `dead` exchange. TTL expiry dead-letters to `reroute` with routing key preserved (no `x-dead-letter-routing-key` set on the retry queue), which routes back to the correct main queue. `x-death` header tracks delivery count (replaces manual `x-retry-count`). `max_retries=5` before routing to `dead`. **`delivery-limit=20`** — the 4.x default; pinned **explicitly via policy** for clarity. It is the broker-side poison backstop. **`dead-letter-strategy = at-least-once` policy applied to all quorum queues** — DLX re-publishes use publisher confirms internally, eliminating silent message loss when the target is full/unavailable; on 4.x this strategy requires the queue use `overflow = reject-publish` (not `drop-head`) + a DLX, both already set below. Backpressure via `x-max-length` + `x-overflow=reject-publish` on **all** queues (main, retry, dead). **`reject-publish-dlx` never used** — circular/undefined on terminal queues. `*.dead` queues get a large `x-max-length` (e.g. 100 000); alert on depth. Topology immutable args in `definitions.json`; tunables (delivery-limit, max-length, TTL, consumer_timeout, dead-letter-strategy) as **policies**. Plain direct exchanges — no consistent-hash routing. **Message priority** (4.x quorum native, 32 strict levels 0–31, default 4, `x-max-priority` ignored) carries per-`callingSystemId` job priority: OutboxRelay sets the AMQP `priority` property from `outbox.priority`; the property survives the `retry`/`reroute` round-trip; no priority-lane queues (§6.1). Strict priority → sustained high-priority load can starve lower levels. |
| **PostgreSQL 16** | One cluster per network. Tables in [ARCHITECTURE.md §3.2 and §5.2](ARCHITECTURE.md). Includes `outbox` and `phase_config` tables. No partitioning day-1. Migrations via OpenShift `Job` (Helm pre-upgrade hook). Year-2: monthly partitioning on `chunk`, `expected_chunk`, `outbox`. |
| **PgBouncer** | Transaction-pooling mode (single pool) in front of each Postgres cluster. |
| **Storage** | RWX assumed for all shared dirs (client-confirmed interim: every pod can read AND write-many to every folder — [`QUESTIONS-TO-CLIENT.md`](QUESTIONS-TO-CLIENT.md) §15/§16); no node-affinity pinning. Work dirs, outbox/target dirs all filesystem-backed. **Proxy delivery dir on B is an RWX PV shared by ProxyListener (writes via proxy, never copies) + Assembly (reads in-place during concat, then best-effort deletes consumed chunks post-COMMIT).** No S3-compatible object store is available ([`QUESTIONS-TO-CLIENT.md`](QUESTIONS-TO-CLIENT.md) §10) — all volumes filesystem-backed; `IStorage` abstracts only the filesystem binding. |
| **Sealed Secrets / external-secrets-operator** | Connection strings, dispatcher credentials. |
| **`phase_config` table** | Holds `max_retries` (default 5) per phase. No heartbeat/sweeper-threshold columns — recovery is broker-level (`consumer_timeout`). Reserved as the home for a per-phase escape-hatch heartbeat if metrics ever demand one (ARCHITECTURE.md §3.3). |
| **`calling_system_config` + `conversion_rule` tables** | Per-`callingSystemId` configuration with `default` fallback (ARCHITECTURE.md §6.1). `conversion_rule` (A only) keys forward + reverse conversion, the Split file-size limit, **and `converter_group`** (engine routing: `image`/`doc`/`video`/`NULL`; §10 #23) by `(callingSystemId, source_format)`; `calling_system_config` (both networks) holds per-caller folders + job SLA. SLA **and `priority`** are independent per network (operator keeps both aligned); reverse-conversion instruction is carried A→B in the mini-manifest, so B has no conversion config. `priority` (per caller, default fallback) → `job.priority` → `outbox.priority` → AMQP message priority on publish (QUESTIONS §20/§21). |
| **RabbitMQ recovery settings** | Client-side watchdog, `consumer_timeout`, AMQP heartbeat 60s, `prefetch=1`, `delivery-limit`/`max_retries=5` — see the "Recovery & Calibration" section below and [ARCHITECTURE.md §3.3](ARCHITECTURE.md). |

## Recovery & Calibration

Canonical model, crash-scenario table, queue-type default, and full calibration: **[ARCHITECTURE.md §3.3](ARCHITECTURE.md)**. Ops quick-reference for this doc:

- **No per-row heartbeat, no per-phase sweeper.** Each worker does idempotent work → single **done-CAS** (`UPDATE entity SET status='Done' WHERE id=$1 AND status='Prev'`) gates the outbox insert + counter; ack after COMMIT. A redelivered/duplicated message loses the CAS and is a no-op. Outbox closes the post-COMMIT-pre-publish window to ~500ms.
- **Recovery latency:** crash/OOM/evict → **seconds** (channel close); hard kill / partition → **~60s** (AMQP connection heartbeat); app deadlock → **client-side watchdog** (`CancellationTokenSource(maxStepDuration)`, seconds–single minutes — reclaims faster than `consumer_timeout`), with `consumer_timeout` (enforced on quorum queues) as the coarser broker backstop.
- **Defaults to set from metrics:** `consumer_timeout` 30min until calibrated → 3–4× measured max step of slowest phase, min 5min, must exceed longest legit step; watchdog `maxStepDuration` = same bound; `prefetch=1`; quorum `delivery-limit=20` — **4.x default; pinned explicitly via policy** (broker poison backstop, parallel to app `max_retries=5`). **Calibrate per engine-group queue** (`files.convert.{image,doc,video}`, `files.reverse.{image,doc}`) — image is sub-second, a 6 GB ffmpeg transcode runs minutes, so a shared timeout would leave hung fast jobs unreclaimed; separate queues + `prefetch=1` also stop a video head-of-line-blocking an image (ARCHITECTURE §3.3, §10 #23).
- **Job-level backstops:** Network B `TimeoutSweeper`; Network A `files_manifest_written_count` + per-file DLQ-terminal + `TimeoutSweeper-A` (§3.7). Both 30-min SLA.
- **Escape hatch:** per-phase heartbeat + single-replica sweeper via `phase_config`, for one long phase only — never global.
- **Client inputs needed** (max step time, acceptable deadlock-recovery latency) drive `consumer_timeout` calibration: [ARCHITECTURE.md §3.3](ARCHITECTURE.md), [`QUESTIONS-TO-CLIENT.md`](QUESTIONS-TO-CLIENT.md) §19.

See [`cas-heartbeat-recovery.drawio`](cas-heartbeat-recovery.drawio) (normal flow, broker-redelivery recovery, outbox post-COMMIT recovery).

## Exception Classification

Transient (retry ≤5 → `*.retry`, 1-min TTL) vs permanent (`status='Failed'` + `failure_reason` → `*.dead`, job continues for other files) vs unknown (transient by default). Full exception-type whitelist + actions are canonical in [ARCHITECTURE.md §3.5 (A)](ARCHITECTURE.md) / [§5.8 (B)](ARCHITECTURE.md) and [`worker-exception-handling.drawio`](worker-exception-handling.drawio).
